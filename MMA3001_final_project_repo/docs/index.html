Project overview

One environmental sensor and one room. Sensor readings (CO2, temperature, humidity, VOC, PM2.5) are used to nowcast the current headcount. A time-of-week schedule baseline is compared with linear regression and support-vector regression (SVR) using time-ordered cross-validation and a single held-out test period.

The API reference is generated from the docstrings (Google style) by pdoc; each function documents its arguments, return values and the errors it raises.

Workflow

StageModulePurpose
1data.pyLoad, clean and align sensor and occupancy data; build the modelling table.
2evaluation.py, models.pyChronological split (with gap); cross-validate the baseline, linear and SVR models.
3sensitivity.pyFeature ablation, SVR settings and training-data requirement, using the training period only.
4evaluation.py, plots.pyCross-validate final models, time them, score the held-out test once, plot.
5floorspace.pyAppendix: repeat on every floorspace (no re-tuning).
–pipeline.pyRuns stages 1–5 and saves the results.

Typical usage

from smart_infrastructure import Config, run_pipeline cfg = Config() # defaults: sensor 6012002000869, room 941f0352-..., Feb-Jun 2024 result = run_pipeline( cfg, env_csv="data/5EnvSensor_MayToDec2024_180kRows.csv", occ_csv="data/5occupancySensor_MayToDec2024_9MRows.csv", out_dir="results", ) print(result["test"]) # final held-out test metrics print(result["improvement"]) # MAE improvement over the schedule baseline # or from the command line: # python -m smart_infrastructure.pipeline --data-dir data --out results

Running the tests

pip install pytest pytest-html pytest-cov pytest --html=tests/test_report.html --self-contained-html --cov=smart_infrastructure

The tests use small synthetic files in the same layouts as the real data, so no real data is needed.
